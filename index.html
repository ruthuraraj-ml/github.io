RAG-LMS · EdTech AI Long-Term Vision

R-B.A.T — RAG-Based Academic Tutor

An offline-first academic learning system that transforms textbooks and PDFs into an interactive tutor, assessment engine, presentation assistant, and evaluation tool. Built around a shared RAG backbone and local LLMs, R.B.A.T. explores how AI can make subject-specific learning more accessible, private, and grounded in course material.

One retrieval backbone, four learning workflows. R.B.A.T. uses shared course knowledge to power tutoring, assessment, presentation, and evaluation experiences through specialised prompting strategies.
Why this matters: R.B.A.T. is my long-term exploration of local-first educational AI systems that can operate without dependence on frontier cloud models.
Tutor Mode
Context-aware Q&A grounded in uploaded textbooks
Assessment Mode
Automated question bank generation from source material
Presentation Mode
Structured note & slide generation from PDF content
Evaluation Mode
Response scoring and feedback against retrieved context
Local LLMs ChromaDB SentenceTransformers pypdf Streamlit Ollama Diagram-Aware Retrieval
Problem
Students preparing for BCM examinations often work with static PDFs and textbooks that cannot answer questions, generate practice material, or explain concepts interactively. Generic chatbots frequently introduce information outside the prescribed syllabus, reducing trust in the learning process.
Key Decision
Chose fully local LLMs over API models so the system runs on student laptops with no internet dependency, no API cost, and no data leaving the machine.
Architecture
Single ChromaDB vector store backing four distinct modes — each mode uses the same retrieval backbone but a different prompt strategy, output format, and evaluation criteria.
⚠ Failure mode: Important information in engineering textbooks often resides inside diagrams rather than surrounding text. Early versions retrieved relevant passages but missed figure-level context, producing incomplete answers. Fixed by introducing a dedicated figure extraction pipeline that indexes diagrams separately and injects semantically relevant visuals alongside retrieved text during response generation.
✅ Outcome: Students can interact with their own course material through tutoring, assessment, presentation, and evaluation workflows while remaining grounded in uploaded textbooks. The system demonstrates how local-first AI can support education without cloud APIs, recurring costs, or external data transfer.

CrewAI · Adaptive Assessment System ✦ New

Adaptive AI Engineer Interview System

An adaptive interview system that selects the next question based on a candidate's live performance, generates it against a fixed competency graph, and scores spoken or typed answers against a rubric — built as two orchestrated CrewAI flows over deterministic Pydantic domain models, not free-form LLM judgment.

The competency graph, difficulty progression, and rubrics are deterministic Pydantic models. The LLM is scoped to exactly two jobs — generate the next question within that structure, and evaluate an answer against the rubric it's given — it never decides on its own what "good" looks like.
Dual CrewAI Flows

CrewAI Pydantic Gemini Groq Whisper-large-v3 Streamlit LiteLLM
GitHub →
Problem
Interview prep tools typically generate static question banks with no adaptivity — difficulty doesn't respond to how the candidate is actually performing, and evaluation is usually a keyword match or a single ungrounded LLM call.
Key Decision
Kept the competency graph, difficulty progression, and rubrics as deterministic Pydantic domain models — the LLM only generates the next question within that structure and scores answers against a fixed rubric, rather than deciding on its own what counts as a good answer.
Architecture
An InterviewController orchestrates two CrewAI Flows — AssessmentGenerationFlow (Strategy Agent selects the next competency/difficulty, Question Agent writes the question) and AssessmentEvaluationFlow (Evaluation Agent scores the answer) — with Gemini and Groq as interchangeable providers via CrewAI's LLM wrapper.
⚠ Failure mode: An early version of the difficulty-selection logic had a rationale mismatch — the system reported choosing a difficulty for one reason while the underlying stub logic used to select it didn't actually match that reasoning. Traced directly to the difficulty-stub logic and fixed before layering the UI on top, rather than patching around it visually.
✅ Outcome: A live, publicly deployed adaptive interview system with real-time speech transcription, and a dual-view UI toggling between a candidate-facing flow and an interviewer "Observability" dashboard rendered as a monospace reasoning trace — shipped and deployed rather than staying a local prototype.

D.A.R.I.A. — Domain-Specific Agentic Research, Intelligence & Analysis System

A memory-driven multi-agent research system that turns a query into an evidence-backed report through planning, hybrid retrieval, critique, reflection, and persistent learning. Combines domain-specific RAG with web research, evidence curation, and a dedicated Research Critic to move beyond one-shot question answering.

Retrieved evidence isn't trusted by default — a Research Critic independently evaluates it, flags missing concepts, and triggers replanning when research quality falls short. Plans, gaps, critic feedback, and final reports persist as memory and get reused in future investigations.

Problem
One-shot research agents retrieve evidence and generate a report in a single pass — there's no check on whether the retrieved evidence was actually sufficient before the report gets written.
Key Decision
Introduced a dedicated Research Critic agent that independently evaluates curated evidence, identifies missing concepts, and can force the graph back to a replanning step rather than letting weak evidence flow straight to the report.
Architecture
LangGraph StateGraph: Memory Agent → Information Needs Analyst → parallel Hybrid RAG/Web Retrieval → Evidence Curator → Research Critic → Reflection Loop → Summarizer → Memory Update.
⚠ Failure mode: The Critic's judgments about evidence sufficiency have no quantitative evaluation harness behind them yet — without RAGAS- or LangSmith-style scoring, the system can confidently approve weak evidence with nothing external to check the critique itself against. Documented as the clear next build, not papered over.
✅ Outcome: Confirmed end-to-end runs producing evidence-backed reports, with research plans and critic feedback persisted and reused across sessions — rated the strongest piece in the portfolio for reproducibility, precisely because its remaining gaps (evaluation infrastructure, single-domain knowledge base) are named rather than hidden.

CrewAI Flow · Multi-Agent · Multi-LLM ✦ New

Logistics Decision Intelligence Platform

A multi-agent decision intelligence platform for supply chain optimization built with CrewAI Flows. Parallel Inventory and Delivery analysis branches converge into a strategy engine, followed by an independent critique stage before recommendations are finalized.

Four specialized LLMs — Groq Llama-3.3-70B, Gemma-4-26B, Gemma-4-31B, Gemini Flash Lite 3.1 are assigned to distinct cognitive roles—inventory analysis, geospatial routing, strategy synthesis, and independent critique—allowing each stage to balance capability, latency, and cost rather than relying on a single model for every task.
Why this matters: Most AI agent systems solve a problem once. This platform explores how multi-agent systems can accumulate organizational knowledge over time and improve decisions across repeated operational cycles.
Parallel Execution
Inventory & Delivery branches run concurrently; and_() sync barrier gates Strategy
Reflection Loop

Delta Memory

Portfolio Comparison
Comparison Agent ranks products by ROI, risk, and complexity
CrewAI Flow Pydantic State Groq Llama-3.3-70B Gemma-4-31B Gemini Flash Lite SQLite Memory Gradio DataCo Supply Chain
Problem
Traditional logistics dashboards surface what happened — late deliveries, stock gaps — but leave a human expert to decide what to do. Each analysis starts from scratch, never building on prior recommendations.
Key Decision
Used CrewAI Flow's and_() synchronization barrier to execute Inventory and Delivery analysis in parallel, ensuring the Strategist only receives a complete operational picture once both branches finish.
Architecture
Four-tier Multi-LLM: Groq Llama-3.3-70B for inventory, Gemma-4-26B for geospatial routing, Gemma-4-31B for strategy synthesis, Gemini Flash Lite for independent critique — each matched to workload and cost.
⚠ Failure mode: Early runs passed critique outputs as stringified dictionaries instead of structured objects, causing downstream revision failures. A normalize_output() layer was introduced to standardize communication across all agent outputs.
✅ Outcome: A context-aware decision platform that accumulates organizational knowledge. The Strategist on run 3 knows what was recommended on runs 1 and 2 — avoiding redundant suggestions and building delta reasoning on top of stored history.

CrewAI · AI Code Debugging ✦ New

AI-Powered Code Debugging Assistant

A multi-agent debugging assistant that turns Python source code into structured debugging reports through collaborative analysis, automated correction, and workflow verification — combining specialized Analyzer, Corrector, and Manager agents with code execution and a live Streamlit dashboard.

Instead of asking an LLM to directly generate complex application objects, a Builder Pattern separates reasoning from artifact construction — lightweight LLM output gets converted into strongly-typed Pydantic domain artifacts, cutting schema validation failures.

CrewAI CodeInterpreterTool Groq Llama 3.3 70B Streamlit streamlit-ace Pydantic LiteLLM
GitHub →
Problem
Asking an LLM to directly generate complex, strongly-typed application objects — analysis reports, corrected code artifacts — is unreliable, since the model is handling both reasoning and object construction at once.
Key Decision
Adopted a Builder Pattern: agents produce lightweight, loosely-structured output, which a dedicated builder layer converts into strongly-typed Pydantic artifacts — separating what the model reasons about from what the application consumes.
Architecture
Sequential CrewAI pipeline: Analyzer Agent → Analysis Builder → Analysis Report → Corrector Agent → Correction Builder → Corrected Code Artifact → Manager Agent → Verification → Streamlit Dashboard.
⚠ Failure mode: The Manager agent's verification stage remains the weakest link — it currently returns unstructured raw text instead of a validated Pydantic object (no output_pydantic), so final verification doesn't yet get the same reliability guarantees as the Analyzer and Corrector stages. Left as an open item rather than hidden.
✅ Outcome: A working sequential debugging pipeline with a strongly-typed schema layer, an execution tracer for observability, and a redesigned Streamlit console — sidebar layout, live code editor, side-by-side diff view — with the Manager verification gap documented as the clear next fix.

PEFT · LoRA & QLoRA Fine-Tuning

Parameter-Efficient Fine-Tuning of BERT & Gemma using LoRA & QLoRA

A hands-on exploration of Parameter-Efficient Fine-Tuning, progressing from LoRA-based adaptation of BERT to QLoRA-based instruction tuning of Gemma 2B — adapting large models by training a tiny fraction of their parameters while cutting memory requirements through 4-bit quantization.

The repository preserves a failed QLoRA attempt on BERT alongside the successful Gemma 2B run — encoder vs. decoder architecture differences don't surface until quantized training actually starts, and that failure is documented rather than edited out.
BERT + LoRA
90.41% accuracy · 591K trainable params (0.54%)
Gemma 2B + QLoRA
97.04%* accuracy · 6.39M trainable params (0.24%)
Quantization
4-bit NF4 via BitsAndBytes
Hardware
Single Tesla T4 (free-tier Colab)
BERT Gemma 2B LoRA QLoRA PEFT BitsAndBytes Hugging Face
Problem
Full fine-tuning updates every parameter and holds full-precision gradients in memory — infeasible on a free-tier Colab T4 (~16GB) for anything beyond small encoder models.
Key Decision
Working within Colab's runtime and memory ceiling, proved PEFT first on BERT with LoRA — cheap to validate — then took the harder step of QLoRA fine-tuning a 2B-parameter decoder model under the same hardware constraint.
Architecture
LoRA adapters in BERT's attention layers (591K trainable params) for stage one; 4-bit NF4 quantization + QLoRA adapters on Gemma 2B (6.39M trainable params) for stage two, using BitsAndBytes for quantized weight loading.
⚠ Failure mode: An initial attempt to apply QLoRA directly to BERT failed — bitsandbytes 4-bit quantization and PEFT's QLoRA path are built around decoder architectures, and encoder-only BERT hit compatibility issues that only surfaced once quantized training actually started. Fixed by keeping plain LoRA (no quantization) for BERT and reserving QLoRA for the decoder-based Gemma 2B.
✅ Outcome: Two working PEFT pipelines on a single T4 — LoRA/BERT at 90.41% accuracy with 0.54% trainable parameters, and QLoRA/Gemma 2B at 97.04%* accuracy with 0.24% trainable parameters — with the encoder-vs-decoder compatibility failure kept in the repo as a documented learning artifact.

Multimodal RAG · LLM Systems ✦ New

Paperwise RAG — Multimodal Research Paper Q&A

A multimodal RAG pipeline for research paper question answering — handling text, tables, and figures from academic PDFs in a unified system. Papers are parsed with Docling (preserving cross-modality structure), embedded with BGE embeddings into FAISS, and answered via Gemini with vision-enabled summarisation for figures and tables. Most RAG pipelines lose structured information in tables and visual content in figures; Paperwise RAG queries each modality separately and merges results before generation.

A real production challenge solved: OOM crashes on high-resolution page rasterisation on large PDFs were fixed by tuning Docling's image scale and disabling full-page generation — the kind of engineering detail that only comes from building against real data.

ReAct Web Research Agent

An autonomous research intelligence system built on the ReAct (Reasoning + Acting) paradigm. Given a topic, the agent generates 6 targeted research questions, then runs a full Thought → Action → Observation → Summary loop per question — combining Gemini for planning and synthesis with Groq LLaMA for fast, tight reasoning at each step.

The multi-LLM split is intentional: Gemini handles structure-heavy tasks (question generation, final report), while Groq LLaMA handles latency-sensitive reasoning loops. Two models, two roles — not interchangeable.
